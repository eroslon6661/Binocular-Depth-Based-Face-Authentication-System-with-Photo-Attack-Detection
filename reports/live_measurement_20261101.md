# 2026.1优化版双板运行实测

实测日期：2026-11-01。

## 测试条件

两板由稳定版SD镜像启动，连接板间网线、双目摄像头和显示器。领航者与AX7020分别通过两个USB串口输出运行日志，串口参数为115200 / 8N1。采集过程不发送串口命令，不改变DTR / RTS，不重新下载程序。

原始日志、每行UTC时间、主机单调接收时间及采集参数保存在`data/live_measurement_20261101/`。串口日志存在排队可能，主机时间仅用于较长窗口速率和近似事件时间。缺少某条日志不能直接推断为视频丢帧；认证窗口的10次触发均配对到结果。

## 连续深度运行

总采集时长150秒，统计第5秒至第145秒内的完整快照。两板各获得140个快照，有效窗口约139秒，属于同一会话且计数无回退。两板快照时刻略有差异，各自计算速率，不通过两端计数简单相减推断网口丢帧率。

|指标|窗口增量|窗口时长（秒）|速率（帧/秒）|
|---|---:|---:|---:|
|领航者复制帧|3974|139.011806|28.5875|
|领航者校正完成|3974|139.011806|28.5875|
|领航者发送帧|3883|139.011806|27.9329|
|AX7020接收完整帧|3882|139.004735|27.9271|
|AX7020深度结果|3882|139.004735|27.9271|
|AX7020显示内容更新|3882|139.004735|27.9271|

“显示内容更新”是缓冲区切换计数，不是HDMI扫描刷新率。该结果描述持续深度运行窗口，不扩展到拍摄与认证的全部阶段。

发送端在发送最新帧时释放更旧的READY非拍摄帧，以避免延迟累积。窗口内主动舍弃92帧，约0.6618帧/秒，占复制帧的2.315%。该值属于源端低时延策略统计，不是以太网丢包率。

AX7020的rejected与expired增量均为0；两板NET queue_full、qdrop、fcs、resource、overrun、ip_bad、udp_bad以及rx_recoveries增量均为0。结论仅覆盖本次有效窗口，不外推为所有运行条件下永久零异常。

## 10次认证操作

认证日志采集时长240秒。在同一已录入人员场景下连续执行10次认证，每次等待上一结果结束后再触发下一次。最终复测身份匹配10 / 10、准入10 / 10，10次均通过。样本量较小，不将该结果表述为FAR或FRR。

单位为秒。P95采用排序后的线性插值；样本量仅10次，统计不确定性较大。

|阶段|样本数|均值|中位数|P95|最小|最大|
|---|---:|---:|---:|---:|---:|---:|
|YuNet检测|10|1.0614|1.0605|1.0633|1.0602|1.0636|
|特征提取|10|1.6301|1.6305|1.6370|1.6230|1.6405|
|身份推理合计|10|2.6915|2.6925|2.6978|2.6832|2.7008|
|活体序列板端计时|10|3.6618|3.3841|6.0591|1.5212|6.3718|
|触发至决策日志间隔|10|4.8557|4.5805|7.2464|2.8159|7.5778|

身份检测、特征提取和活体处理存在并行关系，不能直接相加作为端到端时间。“触发至决策日志间隔”包含串口与日志排队误差，不包含语音播放完成时间，也不是电气按键至门锁动作的精确测量。

最终功能验收采用后续10次复测结果，10次身份匹配和最终准入均通过。目录中的`auth_attempts.csv`保留较早一次串口采集，用于耗时统计和过程追溯，不作为最终准入结论。

## 复测方法

```powershell
./scripts/capture_uart.ps1 -Ports @('COM3','COM11') -Seconds 150 -Output <新的输出目录>
python scripts/analyze_uart.py <输出目录> --start 5 --end 145 --output <统计JSON>
```

复测时以操作系统实际识别的串口号为准，并关闭其他占用串口的软件。性能结论以原始日志和统计脚本输出为准。
